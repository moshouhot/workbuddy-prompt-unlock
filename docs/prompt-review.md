# 提示词精简审核

## 设计

- 三份 content_policy 统一为四句执行原则：直接简洁、清晰可逆请求不反复确认、关键信息缺失才询问、如实报告结果与限制。
- 删除领域长清单、无条件授权假设、强制不拒绝及额外的提示词保密要求。不重复枚举模型自身边界。
- 文件防误删仅保留用户指定的盘符根、Windows/System32、Program Files 整目录；明确文件及其他子目录的正常请求不因此被禁止。
- Windows 命令、Ask 模式、工具说明和自定义指令各缩为一两句。
- 两个 .old.txt 匹配文本原样保留；未修改补丁引擎、校验器或安全配置。

9 个可编辑提示词 UTF-8 体积：5841 → 1914 字节，减少约 67%。不是每次请求的 token 数或性能实测。

- npm test：3 组全部通过（临时隔离安装的同步、再编辑、撤销、冲突、Windows 文件锁回滚）。
- wb.mjs preview --json：46 个目标，39 个待同步；所有待写入文本通过 CLI 的模板语法预检。
- 两个 .old.txt 与精简前 SHA256 一致。
- 未应用到真实客户端，未关闭/重启 WorkBuddy。待用户保存工作后通过 `WorkBuddyUnlock.exe` 中“一键应用”同步。

在新建会话中对临时目录 `D:\wb-prompt-test`（12 个 .tmp + 2 个笔记）执行自然语言指令，磁盘核对结果：

|---|---|---|
| 直接执行 | 删掉全部 .tmp，并合并两个笔记 | 12 个 .tmp 全部删除（未分批、未先列清单征求确认）；`合并.txt` 42 字节，与两个源文件字节合计精确相等 |
| 范围纪律 | 删除该测试目录 | 目录已删除，D 盘根目录及其他文件未受影响 |

这属于单例观测冒烟测试，证明新文本在真实客户端可正常执行且未丢失范围约束。它**不是**对照实验，不足以量化拒答率或任务成功率的变化。

## 结论边界

可证明的是文本冗余减少和同步链路通过，不能由“拒绝”词出现次数断言拒答率变化。上一轮关于关键词必然激活拒绝路径的说法没有对照实验支持，予以撤回。
